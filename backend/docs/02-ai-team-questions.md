## 0. 이미 확인된 사항 (답변 불필요)

| 항목 | 감정 모델 | 시선 모델 |
|---|---|---|
| 모델 | Former-DFER (ResNet18형 + 공간/시간 트랜스포머) | L2CS-Net (ResNet50) |
| 가중치 | `former_trained.pth` 144MB, `module.` 접두사 | `l2cs_trained.pkl` 96MB |
| 입력 | 얼굴 크롭 **16프레임 시퀀스**, 112×112 RGB, `/255` | 얼굴 크롭 1장, 448, ImageNet mean/std |
| 출력 | **5클래스** logit (이름 미상) | yaw, pitch **각도** (90-bin → 도 단위) |
| 프레임워크 | PyTorch 1.8 기준, einops 필요 | PyTorch 1.10+ |

- 두 모델 모두 **얼굴 크롭** 입력. 얼굴 검출기는 베이스라인에 없어 새로 붙여야 함.
- RIT-Net(안구 분할)은 시선 판정에 불필요. MVP에서 제외 예정.
- zip의 모델은 설치가이드 PDF(YOLOv3 + gaze-angle)와 **다른 세트**. 서빙은 zip 기준.
- 세 모델 모두 검증 스크립트만 있고 단일 입력 추론 함수는 없음.
- `nia_demo_dfer.tar`(4GB+)는 다운로드 완료 후 백엔드가 직접 확인 예정.

## A. 가장 급한 것

| # | 질문 | 왜 필요한가 | 가정값 |
|---|---|---|---|
| A-1 | **감정 모델 5클래스의 이름과 인덱스 순서**는? 기획서의 7개 감정(기쁨, 당황, 분노, 불안, 상처, 슬픔, 중립)과 개수가 다르다. 어떤 5개인가? | 이게 없으면 출력을 해석할 수 없어 리포트도 토스트도 못 만든다 | 미정. 답 오기 전까지 인덱스 0~4로만 표기 |
| A-2 | 이 가중치를 **그대로 서비스에 쓰는가**, 아니면 팀이 **재학습**하는가? 재학습이면 1차 납품 시점은? | 백엔드 Phase 2 시작일. 그대로 쓰면 지금 바로 통합 시작 가능 | 그대로 사용, 재학습은 이후 교체 |
| A-3 | 두 모델의 학습 데이터에서 **얼굴 크롭을 어떻게 잘랐는가?** (검출기 종류, 여백 비율, 정사각형 여부) NIA 데이터 문서에 있을 수 있다 | 서빙 크롭이 학습과 다르면 정확도가 조용히 떨어진다 | MediaPipe Face Detection 박스에 20% 여백, 정사각형 |
| A-4 | 검증 스크립트를 **단일 입력 추론 함수**로 재구성하는 작업을 누가 하는가? (`predict_emotion(frames16) -> probs`, `predict_gaze(face) -> (yaw, pitch)`) | 역할 분담. 백엔드가 해도 되지만 모델 내부를 아는 쪽이 검증하기 쉽다 | 백엔드가 작성, AI 팀이 검증 |

## B. 서빙 성능

| # | 질문 | 왜 필요한가 | 가정값 |
|---|---|---|---|
| B-1 | **ONNX 변환**을 해 본 적 있는가? L2CS(ResNet50)는 쉽고, Former-DFER는 einops 연산 때문에 확인이 필요하다 | Render CPU 환경 속도와 메모리. torch 런타임 없이 ONNX Runtime만 실으면 메모리가 크게 준다 | 백엔드가 시도, 실패 시 AI 팀 협의 |
| B-2 | **CPU 추론 시간**을 측정한 적 있는가? (GPU 없는 노트북 기준) | 실시간 3fps 가능 여부 | 미측정. 백엔드가 측정해 공유 |
| B-3 | L2CS 입력을 448에서 **224로 줄여도** 정확도가 유지되는가? | CPU 추론 시간 1/4 절감 | 미확인. 백엔드가 두 크기 비교 측정 |
| B-4 | 조명, 안경, 마스크 등 **알려진 약점**이 있는가? | 리포트 "신뢰도 낮음" 표기 | 미정 |

## C. 판정 규칙 (PM과 함께)

| # | 질문 | 왜 필요한가 | 가정값 |
|---|---|---|---|
| C-1 | 시선 출력이 각도(yaw, pitch)다. **"시선 이탈"의 각도 임계값**을 얼마로 잡을까? 학습 데이터 각도 분포를 알면 정하기 쉽다 | 토스트 알림 규칙 | `|yaw| > 20°` 또는 `|pitch| > 15°`가 3초 지속 |
| C-2 | 감정은 16프레임 묶음 단위로 나온다. **몇 초마다** 추론하고, 어떤 감정이 **몇 초 지속**되면 알릴까? | 토스트 규칙과 서버 부하 | 2초마다 추론, 부정 감정 5초 지속 시 알림 |
| C-3 | 얼굴이 검출되지 않거나 확신도가 낮을 때 **"판정 불가"** 처리는 백엔드가 임계값으로 해도 되는가? | 결측 처리 | 확신도 0.5 미만이면 "불명" |

## 백엔드가 AI 팀에 약속하는 것

- 위 답변을 바탕으로 `Predictor` 인터페이스(입력 타입, 출력 타입, 전처리 규약)를 문서로 정리해 공유한다.
- 가중치를 그대로 쓴다면 **백엔드가 먼저 추론 함수와 CPU 시간 측정을 시도**하고 결과를 공유한다. AI 팀은 검증만 하면 된다.
- 모델이 교체되더라도 인터페이스 뒤 구현만 갈아끼우도록 설계한다.
- 샘플 입력과 기대 출력을 주면 자동 테스트로 결과 일치를 확인해 공유한다.

## 우선 답변이 필요한 순서

1. **A-1** (5클래스 이름) → 없으면 출력 해석 불가
2. **A-2** (그대로 쓰는지, 재학습인지) → 일정 결정
3. **A-3, A-4** (크롭 규칙, 함수화 담당) → 전처리 구현 착수
4. 나머지는 설계 단계 중 순차 확인
